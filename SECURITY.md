# Security Policy

## Scope

Security reports concerning the parser, memory safety, malformed-input handling and build system are welcome.

Please do not use this project to test third-party infrastructure without authorization.

## Reporting

For a private vulnerability report, use GitHub's private security advisory mechanism when available.

Do not publish an unpatched memory-safety vulnerability in the issue tracker before giving maintainers reasonable time to investigate.

## Research boundary

This project is designed for defensive research. Reports should include:

- exact input or fixture;
- version/commit;
- compiler;
- operating system;
- sanitizer output, if available;
- minimal reproduction case.
